# 리뉴얼 및 마이그레이션 기준

## 제품 경험

짧은 한 판 안에서 플레이어가 시장 브리핑을 읽고 종목을 고른 뒤 매수·매도하고, 결과를 바로 이해하도록 합니다. 투자 정보는 실제 조언이 아니라 게임 시뮬레이션임을 유지합니다.

핵심 루프:

1. 페이즈 브리핑에서 시장 이벤트와 주요 신호 확인
2. 종목 가격·변동·위험을 비교하고 보유 현황 확인
3. 거래 수량과 매수 또는 매도를 결정
4. 자산 변화와 종목 반응 확인
5. 페이즈 요약으로 판단을 돌아보고 다음 페이즈로 이동

연습 모드와 랭킹 모드의 차이, 저장된 진행 이어하기, 결과 요약 및 랭킹은 기존 기능으로 취급합니다. 첫 리뉴얼 단계에서는 이 규칙을 재설계하지 않습니다.

## 시각 방향

- **픽셀톤:** 픽셀 모서리, 제한된 팔레트, 작은 장식 그래픽 등 픽셀톤으로 구현합니다.
- **레트로 거래 게임:** STONKS-9800의 레트로 PC 터미널 분위기, 종목 목록·가격·차트가 한 화면에서 읽히는 정보 구성, 시황과 매매가 이어지는 게임 흐름을 참고합니다.
- **프로젝트 고유 해석:** 밝은 파랑을 기본 강조색, 따뜻한 노랑을 보상·선택 강조색으로 둡니다. 상승·하락 색은 현재 데이터 의미와 일관되게 사용하고 색만으로 상태를 전달하지 않습니다.
- **가독성:** 픽셀 장식이 숫자와 한글을 흐리지 않게 합니다. 표와 가격은 정렬하고, 주요 가격·현금·수익률·주문 수량의 위계를 분명히 합니다. 좁은 화면은 브리핑 → 종목 → 주문 → 요약 순서로 재배치합니다.
- **상호작용:** 클릭·키보드 포커스가 분명한 단순 컨트롤, 거래 후 즉각적인 자산 피드백, 의미가 있는 짧은 모션을 사용합니다. `prefers-reduced-motion`을 존중합니다.
- 참조 사이트나 게임의 로고, 이미지, 폰트 파일, 고유한 아트워크를 복사하지 않습니다. 라이선스가 확인된 에셋 또는 자체 제작 에셋만 사용합니다.

## 마이그레이션 순서

1. **기준선:** 기존 라우트, 주요 화면, 매매 동작, 저장 상태 및 랭킹 흐름을 파악합니다. 변경 전후를 비교할 수 있도록 기존 동작을 기록합니다.
2. **공통 표현:** 색·간격·테두리·타이포그래피 같은 작은 토큰과 반복 UI 패턴을 정리합니다. 새 디자인 시스템 프레임워크나 의존성은 추가하지 않습니다.
3. **화면 단위 전환:** 홈/시작, 게임 브리핑과 거래, 요약·결과, 랭킹 순으로 나눠 적용합니다. 각 단계에서 모바일, 키보드 접근성, 로딩·빈·오류 상태를 함께 확인합니다.
4. **데이터 계약 보존:** `useInvestmentGame`의 공개 동작과 `PersistedGameState`, localStorage 키, Supabase 랭킹 계약은 디자인 작업에 섞어 변경하지 않습니다. 데이터 모델을 바꿔야 하면 별도 단계에서 이전 데이터 변환과 롤백 방안을 먼저 정의합니다.
5. **정리:** 모든 사용 화면이 새 표현으로 전환된 뒤에만 중복 스타일을 제거합니다. 구형·신형 화면을 병행하는 토글이나 과도기 설정은 요청이 없으면 만들지 않습니다.

## 완료 조건

- 현재 연습/랭킹 게임 흐름과 기존 경로가 동작합니다.

- 데스크톱과 좁은 화면에서 가격, 변동, 현금, 거래 액션이 읽히고 조작 가능합니다.
- 키보드 포커스, 텍스트 대비, 모션 감소 설정을 유지합니다.
- 변경한 범위에 맞는 lint/build와 실제 실행 화면 확인 결과를 분리해 보고합니다.
